日期：2026-10-26；Pi基线`20013b242e8f28da788a3bd966272f960e56be08`；ESP基线`16aebdd5e2bd17c0addd0b00e3e963cef3252584`。两者本轮fetch均与origin/main一致；本地工作分支`docs/f-day1-interface-freeze`，本轮尚未提交。

## 1. 审查范围与判断口径

本项目是Qt触屏终端、ESP控制桥和可插拔业务模块，目标负载按Pi 3B、一个当前前台用户、两个同时运行模块判断。当前代码支持按实例保存最多8个Pi会话，不能推导双槽硬件已完成。

本轮盘点Pi仓库2764个、ESP仓库1332个Git跟踪文件；全文读取建议报告366个段落/9张表，并核对17张P0任务卡及F第一天审核稿。重点追踪：启动装配→PBR→attach/detach→业务认证→签名包→QLibrary/QML→盆栽历史；同时核对ESP RC522、PBR发送/命令解析、业务TCP/BLE/Wi-Fi、传感器/电源、分区、SDK同步、啸天计划、构建/测试/部署入口。

浏览器/音乐/视频/文件/模糊/桌宠按入口、构建和专项记录核对范围，没有逐行审计所有第三方代码。电视页面仍使用GstVideoItem；CMake同时包含VLC构件，不能用“未来迁移”否认已有构建依赖。CAD仅核目录、资料及已知LFS指针，不宣称板卡电气/结构实物验收。旧`project-code-map.md`列出本Pi checkout不存在的esp路径，仅作历史导航，不作为本轮文件存在性证据。

事实分四类：**源码存在、历史记录、本轮主机结果、目标/待实测**。以下订正文档不实现任何安全功能，不代表代码审计全绿。

## 2. 必须先处置的风险与已订正偏差

### 1）私有固件“已忽略、不公开”的描述与Git事实冲突（发布阻塞）

- 事实：`git ls-tree -r HEAD`确认Pi main跟踪`module-devkit/artifacts/smart-planter-3.0.0/firmware/module_firmware.bin`（1160208字节）及分区、签名包、validation等6个文件；另跟踪示例`embedded_package.json/.tar.zst`共2个文件。产物README称固件含本机私有provision配置；本轮未提取或公布具体值。
- 问题/影响：gitignore不移除已跟踪文件；继续分发可能暴露仍有效设备凭据。不能仅因没有`.pem`就断言安全。
- 最小处理：F/D/L按B-07立即停止再次分发该固件、当日受控核查；若有有效凭据先轮换，再制定取消跟踪/历史处置方案。本轮未删产物、未改历史、未对设备轮换，故风险尚未关闭。

### 2）上一版F稿错误改变锁屏需求（文档已订正，实现待完成）

- 事实：报告原第5.2/5.3节确认锁屏后台任务继续、结果绑定启动用户；上一稿却要求锁屏关库/停worker。
- 问题/影响：照稿开发会让围栏停监测，违背已确认需求。
- 订正：锁屏撤销前台访问，原任务仅保留绑定设备/用户的受限追加能力；测量完成/取消或持续任务停止后才切用户。T-04/09/10/11、IT-012及Journey同步补齐，不能依靠隐藏UI保护数据。

### 3）报告旧分期与14天P0清单相冲突（文档已订正）

### 4）SDK“一致/同步错误原因”的报告不符合当前代码（文档已订正，T-02待修复）

- 事实：两仓共有506个SDK文件，503个字节相同，3个不同：`README.md`、`docs/MAINTENANCE.md`、`sdk/SOURCE-MANIFEST.json`；Pi独有8个为上述产物/嵌入包，ESP独有2个为啸天需求/计划。不能称所有共有文件相同。
- 本轮检查：Pi `python3 tools/sync_module_devkit.py --check`缺13项ESP源映射而失败；ESP同命令已不再引用缺失Pi文件，而以“source copies match but manifest needs refresh”失败。ESP清单464项中461项元数据与当前映射不符，源/副本内容检查未报不同。
- 最小处理：D主责、Z协作，第2天前提交Pi C ABI/工具与ESP固件的显式来源/commit/路径/哈希和校验路线；本轮不运行`--write`或覆盖副本。完整发布自动化仍可P2，但P0来源检查不得跳过。

### 5）盆栽已有明文历史，不能“新建SQLCipher”后就算隔离完成（任务已补齐）

- 事实：`module-devkit/examples/smart-planter/module.cpp:20-28`以module_instance的散列命名JSON，`History.h:59-68`原子写入明文温度历史，没有userId。实例散列是文件名，不是加密。
- 问题/影响：旧路径继续读写会绕过每用户库，或把旧实例记录显示给另一位用户；直接删除又有数据损失。
- 最小处理：T-10/11/13统一迁到可信SQLCipher API并禁用P0旧路径；原文件保留且P0业务不可读，无归属记录不得自动分给首个用户。后续迁移/删除须用户确认。

### 6）当前认证/信任不等于AEAD、设备证书或OS隔离（保持为P0缺口）

- 事实：Pi PBR只有CRC16；`HostEventDetector`只分发attach/detach，无RFID用户链；`HotspotLanTransport`用QTcpSocket；ESP TCP token明文往返，BLE GATT未强制安全属性；ModuleManager在主进程QLibrary执行，并加载模块任意QML。Pi没有通用AuthService/用户SQLCipher/worker安全服务。
- 问题/影响：raw UID、业务数据和token无法由当前协议保证保密；签名包/首次信任不能约束原生插件的宿主权限。浏览器SQLite和音乐登录不是用户安全库/终端身份。
- 最小处理：按T-03/04/07/10/11/12实现，不降级；P0固定LAN TLS、BLE禁用，具体成熟密码协议/参数仍须D/Z/L提交及F专项审核。桥板项目签发与模块逐台DIY身份分开，Secure Boot/Flash Encryption为生产目标，未验证现有设备开启。

### 7）P0拔槽策略是有意变更，不是当前行为（任务及兼容性已订正）

- 事实：`ConnectionManager.cpp:130-138`detach只置contact=false，保留已加载/就绪无线业务；`:22-26`桥掉线仅更新状态；`tests/session_test.cpp`多处断言拔触点后仍ready。
- 问题/影响：只改F文案会遗漏调用方、页面和既有测试；也会让“双槽撤销”在实现中不生效。
- 互动确认后的订正：保留触点/业务分离。任务按device/session/task/原用户绑定，slot只表示物理位置；拔出释放槽位但安全有效的无线任务继续。桥失联禁止新刷卡/绑卡/物理确认，已有任务继续且已登记用户可本机PIN解锁管理。恢复重验控制身份/位置，不无故重建业务，冲突不转移授权。T-05/11/16更新实现和测试；当前代码未修改。

### 8）目标Qt/桌面与历史通过记录混用（文档已订正）

- 事实：目标是用户指定Qt6.5.3/ARM64 Bookworm/Wayland；盆栽VALIDATION记录Qt6.4.2与labwc/Wayland；CMake最低Qt6.4，并额外依赖VLC/GStreamer/WebEngine等。

- 订正：T-02/10记录实际版本、插件路径和SQLCipher加载证据。本轮主机测试显式使用本机Qt6.10.1，仅为主机逻辑结果，不是Pi6.5.3验收。

### 9）啸天路径、编号和传感器能力不能猜（文档已订正）

- 事实：ESP仓`module-devkit/examples/xiaotian/`仅两份计划/需求，Pi仓无该目录；0x19是旧候选，无已核实中央注册表。盆栽还发布电池/供电/保护字段，充电状态当前null，外电检测未接线的历史记录显示unknown。

- 订正：啸天目标在既有示例下新增firmware，D/L查重确认module_id，Z在Pi做受控页面；L实测电平/采样/去抖。P0全部字段含电量/供电，无效显示unknown而非伪正常；GPIO、器件、到货状态本轮均未确认。

### 10）任务依赖和全套测试通过不能凭文字推断（文档已订正）
