## 核心验收用例

### E2E-001：刷卡至用户会话

1. 桥板使用项目签发测试身份建立经过认证的 PBR AEAD 会话。
2. 真实 RC522 产生事件；Pi 验证 tag、bridge_id、boot_id 和 event_id。
3. Pi 短暂使用 raw UID，计算本机密钥派生索引。
4. 页面只显示低敏 PIN 页；输入正确 PIN 后打开当前用户会话。

通过：未认证/重放/过期事件拒绝；PIN 前不读用户数据；raw UID 不落盘/日志。

### IT-012：SQLCipher跨用户隔离

用户 A/B 各写一条不同标记；以 A context 读取 B、以错误 key 打开 B DB、退出后重用旧 session。

通过：所有越权读取和错误 key 均失败；用户文件使用 SQLCipher；DB/WAL/log/temp 无 PIN、raw UID 或明文健康记录。

### IT-014：模块业务数据加密和认证

P0固定LAN profile，抓取链路并注入无TLS TCP、错误设备key、过期会话和TLS协商失败；若P0启用BLE，再测试未配对GATT和错误应用认证；未启用的BLE profile必须确认被禁用。

通过：P0 LAN业务lane必须TLS+设备认证；BLE若启用则强制加密和应用认证，否则连接被拒绝；抓包不能恢复传感器明文或凭证；任何错误均不回退旧明文协议。

### IT-013：基础worker隔离

以 worker UID 启动模块代码，尝试读取 DB、Pi主目录、任意文件和公网地址；再令 worker 崩溃并观察宿主。

通过：DB/密钥/任意文件访问拒绝；无公网路由；worker崩溃不带崩宿主，资源被回收。验证 Pi 实机规则生效，不只检查配置文件。

### E2E-004：啸天真实两路输入

两对真实探头分别遮挡/恢复，观察去抖、每路 event_id 和页面状态。

通过：两路互相独立、无串线；P0不将速度精度、户外距离或闭合围界列为通过项。

### E2E-006：双模块同时运行

同时连接盆栽与啸天；持续接收盆栽全部传感器数据（确认LAN TLS/BLE加密和身份认证）并交替触发啸天两路；拔出一槽后观察另一槽。

通过：event/user/slot/device context 不串；拔槽、重启其中一模块不停止另一模块；桥板重启后重新认证。

### Journey-001：完整P0旅程

```text
桥板项目测试身份认证
→ 两个模块分别认证
→ 用户刷卡并通过PIN
→ 盆栽全部数据可见
→ 啸天两路真实输入可见
→ 两模块同时运行
→ 拔出一个槽
→ 另一槽继续工作
→ 用户退出/锁屏
→ 旧会话和模块数据API被拒绝
```

任一步骤身份、授权、SQLCipher、worker沙箱、事件路由或实机验收失败，P0 即不通过。
