# ESP32 多传感器复合产品选题与案例线索（40项）

日期：2026-10-26 · 选题与演示方案版（来源核验状态见文末）

## 使用说明

本文用于比赛产品选题。案例筛选标准是：

- 有明确使用者和具体使用情境；
- 至少两类传感信息共同判断一个状态，或共同决定一个提醒；
- 面向 2～4 周的展示样机筛选；专业探头、模型训练及长期现场验证不默认能在此周期完成；
- 优先选择防灾应急、养老助残、乡村生产和生活创意；
- 摄像头/麦克风类产品只建议现场显式提示，不保存原始影像或录音。
- 样机只做声、光、文字或震动提醒；参考项目即使有电机、阀门或泵控制，也不作为本次必做功能。

**阅读口径：40 项是候选产品构想，不是 40 个已经核实的同款成品。** 表中融合规则、传感器扩展和演示流程是建议方案；论文、教程或机构资料仅支持其实际描述的部分。计时、按钮、无线通信和同一探头计算出的变化率不算额外的传感器。选定制作前至少确认两类独立感知确实参与同一次判断，不能只是分别显示读数。

案例不等于直接照搬方案，也不代表原创性、专利可实施性或产品安全认证已经确认。表中“复合感知与结果”是本项目可制作的候选构想；参考链接是核查线索，其实际支持范围以文末核验记录为准，不保证原案例实现了表中每一个融合判断。普通传感器组合本身不构成创新；比赛差异应放在目标用户、产品形态、离线体验、判断流程和实际服务结果上。2～4周是基于常见开发板的原型估算，取决于部件采购、团队经验和样机加工。

数量按产品用途计，不按独立论文或独立技术计：例如#8与#18、#21与#34属于相近技术的不同情境，不应包装成40项独立发明。

## 五、40 项样机怎样证明“复合判断”

以下均为**建议演示流程，不是来源项目已实现的功能**。A：常见模块、规则判断，优先；B：需要结构制作、探头校准或多人测试；C：专用设备、数据集或长期验证，先做流程模型。难度为选题估算，不是工期承诺。

每项至少演示“正常、单一信号变化、联合条件成立”三组情况，并展示是什么条件导致提醒。阈值按器件、个人和现场校准，不把任意演示数值当作安全标准。

| # | 联合判断的最小规则 | 桌面演示方法 | 难度/主要限制 |
|---:|---|---|---|
| 1 | 手指弯曲形状和手腕姿态同时符合才输出词组 | 同一握拳配不同腕向，输出不同短语或拒识 | B：逐人校准；先做5～8个自定义手势 |
| 2 | 检测到入内，距离/姿态异常且持续无活动才提示查看 | 隔间模型内改变目标高度和活动，不让“关门”单独触发 | B：遮挡、布局及误报需实测 |
| 3 | 离座后雷达报告疑似倒地，且未恢复才提醒 | 靠垫模拟座位占用，雷达目标模拟低位静止 | C：普通存在雷达不能直接识别跌倒；不用真人摔倒 |
| 4 | 床压释放且床边有人、环境暗时提示起身风险 | 移走床垫配重并遮光；只遮光不提醒 | A：需测试压力漂移 |
| 5 | 多处活动和用水/开门模式均偏离用户设定时提示确认 | 小房屋模型按正常与异常顺序触发传感器 | B：短演示不能证明长期健康状态 |
| 6 | 确认门铃声事件并检测到室内有人，才转发佩戴端提醒 | 播放授权门铃样本；空房不震动 | B：门铃声音识别与噪声误报 |
| 7 | 前方超声波与接触积水探头共同决定提醒类别和级别 | 泡沫障碍、浅水盘，比较单项与同时出现时的震动模式 | B：接触后才知有水，不能替代白杖和定向行走训练 |
| 8 | 人离灶后仍有高温或烟气上升才升级提醒 | 用温热物体与人体目标；烟气输入可标注为模拟 | B：无明火、无燃气、无人身暴露实验 |
| 9 | 床垫空载、已经过床边且迟迟未回床，结合门状态提醒 | 配重离床、通过红外、模拟回床和未回床 | A：正常夜间活动也可能需要人工确认 |
| 10 | 轮椅移动且对应方向接近障碍时提醒 | 玩具底盘、距离探头和轮速计；静止靠墙不持续报警 | B：只辅助提醒，不自动驾驶 |
| 11 | 降雨与水位/上升趋势共同决定提醒级别 | 透明水槽缓慢与快速加水，配合雨滴输入 | A：水位变化率只是派生值，不算第三个传感器 |

## 六、软件如何服务普通用户

这些是选题时应考虑的最小使用流程，不代表当前终端已实现：

1. **选择用途**：显示“我在帮助谁、会提醒什么”，而不是要求用户选择GPIO和协议。
2. **引导摆放和校准**：例如空衣架归零、空床/有人标定；每路显示有效、缺失或需要校准。
3. **解释提醒**：显示“有衣物 + 正在下雨”，让用户知道为何提醒；传感器失效不得显示正常。
4. **确认与暂停**：用户可以确认已处理、短时暂停；求助类必须有取消误触发入口。
5. **最小记录**：只保留必要事件时间和摘要，支持清除；影音现场提示、不保存原始影音。不依赖云端才能发出本地提醒。

软件价值是让同一类模块更换用途时仍能被普通人配置、理解和使用，而非为了凑功能增加后台系统。各成品独立服务具体人群，不以家庭联网为主线。

**与现有项目的边界**：[智能盆栽示例](../module-devkit/examples/smart-planter/README.md)已有环境读数与历史看板，但明确没有土壤湿度和浇水硬件。可参考其无效/过期提示和历史展示；不能把这些选题写成现有模块已具备的功能，也不再把单纯环境看板算作新复合产品。

## 优先制作建议

下列为候选优先顺序，**不是要求2～4周全部做完**。先选2～3件，至少覆盖一个辅助沟通、一个生活创意和一个防灾方向；有专人负责和现成器件再增加：

1. **手势沟通器**：已有明确保留决策，展示辅助沟通价值。
2. **晾衣收衣提醒架**：雨滴与衣架称重共同判断；空架淋雨不提醒、有衣淋雨才提醒，不做电动收回。
3. **门前漫水提醒柱（#11）**：透明水槽加雨检/水位，展示单独下雨不等于危险水位。
4. **床边起身风险提醒器（#4）**：压力、人体活动和光照共同判断，器件普通；原文摘要只支持PIR与光照，床压为拟加，全文尚未核实。
5. **村仓进水巡查箱（#14）**：门内外两区模型，展示“外部关注、内部进水升级”，比多灾种读数拼盘更聚焦。
6. **鸡舍夜间关门检查盒（#24）**：光照、门磁和通道检测，只提醒不控制，容易安全展示。
7. **卫生间久留提醒器（#2）**：在隔间模型上演示人体进入、距离变化和长时间静止判断；需测试布局与误报。

**暂不排入首批**：水泵故障分类、鱼塘溶氧、食物变质判断、滑坡预测和生理热风险。它们适合后续验证，但专用探头、样本采集或安全证明不能靠桌面演示替代。车内遗留提醒若选择，只做无乘员模型，不做真实车载安全承诺。
